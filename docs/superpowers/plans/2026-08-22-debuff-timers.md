# Debuff Timers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track DoT, slow, and resist debuffs on mobs as live countdowns in a mob-grouped deck in the Electron desktop app, alongside the existing mez and lull control deck.

**Architecture:** One new Tk-free engine module, `loremaster/debuff_timer.py`, mirroring `lull_timer.py`. It holds a curated spell table and a `DebuffTracker` with two internal paths sharing one pending-cast mechanism: DoTs resolve their target from `dot_out` tick messages, slow and resist resolve theirs from landing prose correlated against a pending local cast. Snapshots travel the existing JSONL protocol to a new React deck. Nothing in `mez_timer.py` or `lull_timer.py` is refactored.

**Tech Stack:** Python 3 stdlib only (no pip packages — a hard project constraint), TypeScript, React, Electron.

**Spec:** `docs/superpowers/specs/2026-08-22-debuff-timers-design.md`

## Global Constraints

- **System Python, no pip packages.** The engine must import stdlib only.
- **Tk-free engine modules.** `debuff_timer.py` must not import `tkinter`; it is loaded by the headless desktop worker.
- **No game-memory access or injection.** Log parsing only.
- **Electron only for UI.** `MezTimerOverlay` in `loremaster.py` is not modified.
- **Coverage ceiling is level 50**, classes SHM/ENC/BST for slow, SHM/ENC for resist, SHM/ENC/BST/NEC/DRU for DoTs.
- **Durations are level-scaled then rank-scaled**, cap applied to the level-derived base before rank scaling.
- Reference data lives at `loremaster/tests/fixtures/debuff_spell_reference.json`, regenerated by `tools/scrape_debuff_spells.py`. It is the provenance for the table and the source of the endpoint assertions.

**Codebase conventions — these override the illustrative snippets below:**

- **Tests use `unittest`, not pytest.** CI runs
  `python3 -m unittest discover -s . -p 'test_*.py'` with
  `working-directory: loremaster/tests`. Test classes subclass
  `unittest.TestCase` and use `self.assertEqual` and friends.
- **Timestamps are `datetime` objects, not floats.** Existing tests define
  `BASE = datetime(2026, 8, 6, 12, 0, 0)` and offset with `timedelta`.
- **Argument order follows `lull_timer.py`:** the subject comes first and the
  timestamp second, e.g. `begin_cast(spell_name, occurred_at, caster_level=50)`,
  `observe_landing(target_name, occurred_at, ...)`,
  `observe_kill(target_name, occurred_at)`, `snapshot(now, *, limit=3)`.
- **Caster level is a resolve-time parameter, not tracker state.**
  `resolve_lull_spell(name, caster_level=...)` is the model to follow.
- **Reuse `duration_confidence`** (`"exact"` / `"conservative"`) from
  `lull_timer.py` rather than inventing an `duration_confidence` boolean. DoT rows
  confirmed by a tick are `"exact"`; slow and resist countdowns are
  `"conservative"`.
- Test modules bootstrap imports with
  `sys.path.insert(0, str(Path(__file__).resolve().parents[1]))`.

Formulas, keyed by the `duration_formula` field. `None` means fixed duration,
in which case `duration_cap_ticks` *is* the duration.

```python
SERVER_TICK_SECONDS = 6

def _half_up(numerator: int, denominator: int) -> int:
    return (numerator * 2 + denominator) // (2 * denominator)

DURATION_FORMULAS = {
    "level_half_roundup": lambda level: _half_up(level, 2),
    "level_half_plus1":   lambda level: level // 2 + 1,
    "level_x30":          lambda level: level * 30,
    "level_x2_plus10":    lambda level: level * 2 + 10,
}
```

`duration_ticks` applies the formula, clamps to `duration_cap_ticks`, then
applies rank via `mez_timer.scaled_duration_ticks`, which is imported rather
than reimplemented.

Rank parsing reuses `mez_timer.split_spell_rank` and the name normalisation
helper, both already tolerant of case and apostrophes.

The 46-row table is generated from the reference JSON; every row carries its
`published_endpoints` so the assertion above has something to check.

- [ ] **Step 3: Implement `DebuffTracker`**

A pending cast is `(spell, cast_at)` held in a short deque. A landing consumes
the newest pending cast whose spell's `landing_family` matches, within a
correlation window. A DoT tick consumes the newest pending cast whose spell
name equals the tick's spell, or, if none is pending, refreshes an existing
row for that target and spell.

Active state is keyed `(target, spell_name)`. Expiry is
`landed_at + duration_ticks(...) * SERVER_TICK_SECONDS`. A DoT row is retained
past expiry while `last_tick_at` is within two server ticks of `now`.

`snapshot` groups active rows by target, sorts rows within a group by
remaining time, sorts groups by their most urgent row, truncates to
`mob_limit`, and reports the truncated count as `overflow`.
